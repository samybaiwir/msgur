API & client crypto

One endpoint. No auth, no token, no key on the wire. You do the crypto; the server stores an opaque blob and hands it back exactly once.

This is the whole point of secret: it's zero-knowledge. The 256-bit key is generated on your machine and lives only in the URL #fragment — browsers never send the fragment to the server, and neither should you. So the operator (me, the parrot) physically cannot read your secrets. The API is open precisely because there's nothing to leak; a per-IP rate limit keeps the database from being spammed.

The endpoint

Interactive docs: /api/docs (Swagger UI) · machine spec: /api/openapi.json (OpenAPI 3.1).

POST /api/v1/secret  —  JSON in, JSON out. Request:

FieldTypeNotes
messagestring (required) The base64url payload iv ‖ ciphertext ‖ tag (see the byte format below). Not your key — the key never appears in this request.
ttlint seconds (optional) Lifetime before an unread secret self-destructs. Coerced to the allow-list (1h / 6h / 1d / 7d / 30d) and hard-clamped to 30 days. Default 7 days.

Response (201 Created):

FieldTypeNotes
idstringThe secret id — the path segment of the read-once URL.
expires_atintUnix epoch seconds when it expires.
link_prefixstring The link minus your key. The full shareable URL is link_prefix + key — you append the base64url key you kept client-side.

Exceed the rate limit and you get a clean 429 (JSON); a malformed body gets a 422. Reading a secret is a separate one-time GET /fetch/<id> that deletes it on read.

The byte format (v1)

One format, every language. Get these bytes right and Python, Node and a browser all interoperate.

  • Primitive: AES-256-GCM (authenticated encryption — confidentiality and tamper-detection).
  • key: 32 random bytes (256-bit), base64url no padding (43 chars). Goes in the URL #fragment. Never sent to the server.
  • payload: iv ‖ ciphertext ‖ tag, base64url no padding. This is the message field; the server stores it verbatim.
{% raw %} 
payload bytes:
+----------------+------------------------+----------------+
| iv (12 bytes)  | ciphertext (N bytes)   | tag (16 bytes) |
+----------------+------------------------+----------------+
 0              12                      12+N           12+N+16
{% endraw %}
  • iv / nonce: 12 bytes (96-bit), random per message. 12 is mandatory — a non-96-bit nonce makes the two stacks derive it differently and diverge.
  • tag: 16 bytes (128-bit). Both Python AESGCM and WebCrypto already append the tag to the ciphertext — never split it by hand.
  • AAD: none (empty).
  • base64url, no padding: standard base64 with +/ → -_ and all = stripped. To decode, re-pad to a multiple of 4 with = first — skipping that is the #1 cross-language bug.

Copy-paste

Python (pip install cryptography)

{% raw %} 
import os, json, base64, urllib.request
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

def b64url(b): return base64.urlsafe_b64encode(b).rstrip(b"=").decode()

secret = "the eagle lands at midnight"
key = os.urandom(32)                       # 256-bit key — stays on your machine
iv  = os.urandom(12)                       # 96-bit GCM nonce, random per message
ct  = AESGCM(key).encrypt(iv, secret.encode(), None)   # returns ciphertext || tag
payload = b64url(iv + ct)                  # iv || ciphertext || tag -> base64url

req = urllib.request.Request(
    "https://secret.cybernoob.io/api/v1/secret",
    data=json.dumps({"message": payload, "ttl": 86400}).encode(),
    headers={"Content-Type": "application/json"})
resp = json.load(urllib.request.urlopen(req))

print(resp["link_prefix"] + b64url(key))   # append the key the server never saw
{% endraw %}

Node (Node 18+, save as .mjs)

{% raw %} 
import { webcrypto as crypto } from "node:crypto";

const b64url = (b) => Buffer.from(b).toString("base64")
  .replace(/\+/g, "-").replace(/\//g, "_").replace(/=+$/, "");

const secret = "the eagle lands at midnight";
const key = crypto.getRandomValues(new Uint8Array(32));   // stays on your machine
const iv  = crypto.getRandomValues(new Uint8Array(12));
const k   = await crypto.subtle.importKey("raw", key, { name: "AES-GCM" }, false, ["encrypt"]);
const ct  = new Uint8Array(await crypto.subtle.encrypt(
              { name: "AES-GCM", iv }, k, new TextEncoder().encode(secret)));  // ct || tag

const payload = new Uint8Array(iv.length + ct.length);    // iv || ct || tag
payload.set(iv); payload.set(ct, iv.length);

const resp = await fetch("https://secret.cybernoob.io/api/v1/secret", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ message: b64url(payload), ttl: 86400 }),
}).then((r) => r.json());

console.log(resp.link_prefix + b64url(key));              // append the key
{% endraw %}

curl (the raw HTTP shape)

curl can't do AES-GCM itself — encrypt client-side first (e.g. with the Python above), then POST the resulting payload. The key never goes in this request.

{% raw %} 
curl -X POST https://secret.cybernoob.io/api/v1/secret \
  -H "Content-Type: application/json" \
  -d '{"message": "<base64url-payload>", "ttl": 86400}'

# 201 ->
# { "id": "AbC123",
#   "expires_at": 1780000000,
#   "link_prefix": "https://secret.cybernoob.io/AbC123#" }
#
# shareable link = link_prefix + <your-base64url-key>
