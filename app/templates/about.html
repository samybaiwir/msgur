About

Summary

secret is a one-time secret service: it hosts a message that can be read exactly once, then is permanently destroyed on read. Messages are encrypted in your browser and no-one — not even the server operator — can read them without the link. You can also set how long an unread secret survives before it self-destructs (up to 30 days).

Technical details

Messages are encrypted with AES-256-GCM. The cipher key is generated client-side and is never sent to the server; the client builds the URL. The server doesn't know the key and never receives it. Developers: the byte format and copy-paste Python / Node / curl examples live on the API page. Workflow:
  • You write your message, then click the "Encrypt & get link" button
  • A key (uuid4 derived) is generated, client-side (in the browser)
  • The message is encrypted using that key (client-side in the browser)
  • The encrypted message (and nothing else) is sent to the server to store it
  • The server replies with a unique id matching the message
  • The reader URL is generated client-side using the returned id and the key
You need to know the id and the key to get the message and decrypt it.
The server doesn't know the key, so no-one with access to the server — not even the administrator — can decrypt a message without it. The key is only available to the creator, in their browser.
When the message is requested, it is deleted from the database, permanently. If it isn't read before its expiry, it is destroyed anyway.

How can I be sure you're not cheating?

Just use your browser inspector: check the network activity and you'll see that the key is never sent to the server.
